# 앵파크 실시간 규약 v1

앵파크에서 지금 접속한 사람들의 앵무가 서로 보이게 하는 규약이다. 서버는 `realtime/` 모듈(독립 Spring Boot 앱, 일기 API인 `backend/`와 따로 띄운다), 클라이언트는 `frontend/src/lib/parkNet.ts`.

## 1. 원칙

- 순수 WebSocket, 주소는 `/ws`. 메시지는 JSON 한 개씩이고 모두 `type`을 가진다.
- 상태는 서버 메모리에만 둔다. 서버를 다시 띄우면 모두 다시 접속해서 hello부터 한다. 서버를 여러 대로 늘릴 때 Redis를 붙인다.
- 로그인과 무관하다. 앵로그 계정이 없어도 들어온다. 그래서 이 서버는 누구인지를 믿지 않는다. 이름과 모양은 서버가 정리해서 보여주기만 한다.
- 자유 채팅은 없다. 말은 정해진 문구의 번호만 오간다(`frontend/src/lib/phrases.ts`). 문구를 늘릴 때는 끝에 붙이고 `angpark.phrase-count`를 같이 올린다.

## 2. 채널

- 한 채널은 공원 하나이고 정원은 `angpark.channel-capacity`(기본 50).
- 새로 온 사람은 자리가 있는 가장 앞 번호 채널로 간다. 다 차면 새 채널을 연다. 비어 버린 채널(1번 제외)은 닫는다.
- pid는 채널 안에서만 쓰는 번호이고 다시 쓰지 않는다.

## 3. 클라이언트 → 서버

| type | 내용 | 제한 |
|---|---|---|
| hello | `{v, look, x, y, z, ry}` 처음 한 번 | v가 다르면 4001로 닫힘 |
| ping | `{t}` | heartbeatMs(10초)마다 |
| move | `{x, y, z, ry, m}` 바뀌었을 때만 | 150ms보다 잦으면 버림 |
| look | `{look}` 다시 꾸몄을 때 | 2초에 한 번 |
| emote | `{id}` "chirp" 또는 "dance" | 0.6초에 한 번 |
| say | `{n}` 문구 번호 0..phraseCount-1 | 1.5초에 한 번 |

look은 `{name, species, colors: {face, head, body, wing, tail}, home}`.

- name은 보이지 않는 문자를 지우고 공백을 줄인 뒤 12자까지. 비었거나 금칙어가 들어 있으면 "앵무".
- species는 LOVEBIRD, BUDGIE, COCKATIEL, QUAKER, GREEN_CHEEKED_CONURE, OTHER 중 하나. 아니면 OTHER.
- colors는 `#RRGGBB`. 아니면 그 부위만 기본색.
- home은 앵로그 아이디(`[a-z0-9_]{3,20}`)이고, 다른 사람이 "집에 놀러가기"를 누를 수 있게 한다. 서버가 확인하지 않으므로 남의 아이디를 적을 수도 있다. 결과는 공개된 방으로 가는 링크라 v1에서는 허용한다(아래 7. 남은 일).
- 거부하지 않고 조용히 고친다. 고장 난 클라이언트도 들어올 수 있게 하려는 것.

m(자세 번호): 0 가만히, 1 걷기, 2 날기, 3 춤, 4 신남, 5 짹짹, 6 깃털 다듬기. 그 밖은 0.
위치는 x, z가 ±60, y가 0..12로 잘리고 소수 둘째 자리까지 반올림한다. 숫자가 아니면 입구(0, 0, 23)에 선다.

## 4. 서버 → 클라이언트

**welcome** (hello에 대한 답)
```json
{"type":"welcome","v":1,"pid":7,"channel":1,"capacity":50,"online":3,
 "presenceMs":200,"moveMs":200,"heartbeatMs":10000,
 "players":[{"pid":3,"look":{...},"x":1.5,"y":0,"z":20,"ry":0.3,"m":0}]}
```
players에 나는 빠져 있다.

**presence** (채널마다 200ms에 한 번, 바뀐 게 있을 때만)
```json
{"type":"presence","channel":1,"online":3,
 "joined":[{"pid":8,"look":{...},"x":0,"y":0,"z":23,"ry":0,"m":0}],
 "moved":[[3,1.6,0,19.5,0.3,1]],
 "left":[5],
 "looks":[{"pid":3,"look":{...}}],
 "emotes":[[3,"chirp"]],
 "says":[[3,5]]}
```
- 빈 목록은 빠진다. 내 pid가 들어 있을 수 있으니 클라이언트가 거른다.
- 한 틱에 여러 번 움직이면 마지막 위치만 간다. 이번 틱에 들어온 사람은 joined에 최신 위치로 한 번만 나온다.
- welcome 직후의 presence가 welcome에 이미 있던 사람을 joined로 다시 보낼 수 있다. 클라이언트는 이미 있는 pid를 무시한다.
- left는 항상 보낸다. 들어오자마자 나간 사람도 그 사이에 누군가의 welcome에 실렸을 수 있기 때문이다.

**pong** `{t, now}`, **error** `{code, message}`. code는 BAD_MESSAGE, NOT_READY, UNKNOWN_TYPE.

## 5. 왜 묶어서 보내나

움직임을 받는 즉시 모두에게 보내면 50명이 초당 5번 움직일 때 채널 하나에 초당 12,250개를 보낸다. 200ms마다 한 번 묶으면 초당 250개다. 고해야지 realtime-server에서 검증한 방식이고, 그 서버에 붙지 않고 방식만 가져왔다.

## 6. 닫힘 코드

| 코드 | 뜻 |
|---|---|
| 4001 | 규약 버전이 다름. 클라이언트는 다시 붙지 않는다 |
| 4002 | 10초 안에 hello가 없거나, 30초 동안 ping도 move도 없음 |
| 4004 | 한 IP에서 연결이 20개를 넘음 |
| 4005 | 메시지가 2KB를 넘음 |

클라이언트는 4001이 아니면 1.5초, 3초, 6초... 최대 30초 간격으로 6번까지 다시 붙는다.

## 7. 남은 일

- home 확인: 앵로그 서버가 서명한 짧은 토큰을 hello에 실어서, 그 아이디의 주인일 때만 home을 붙인다.
- 서버 여러 대: 채널 상태를 Redis로 옮기고 presence를 Pub/Sub으로 나눈다.
- 신고와 차단: 이름 신고(이름만 자유 입력이라 여기만 위험).
- 부하 시험: 채널 하나에 50명, 서버 하나에 채널 20개.
